# GamePanelHUD — SPT 4.1.6 port

A community port of [kmyuhkyuk's GamePanelHUD](https://github.com/kmyuhkyuk/GamePanelHUD)
and its hard dependency [KmyTarkovApi](https://github.com/kmyuhkyuk/KmyTarkovApi),
adapted to **SPT 4.1.6**.

Upstream last published **GamePanelHUD 3.4.0** and **KmyTarkovApi 1.5.0**, both for SPT 4.0.
No 4.1 build has ever been released upstream.

> **This branch — `spt-4.1-port` — is the source of every published binary.**
> The default branch is kept in sync with it. If you are reading `master` and see
> `ToolsVersion 15.0` / `net472` project files, you are looking at upstream's 4.0 code,
> not this port.

## How to build

### 1. Requirements

| Tool | Version |
|---|---|
| .NET SDK | 8.0 or newer (the projects target `netstandard2.1`) |
| SPT | **4.1.6** client, installed (needed only for reference assemblies) |

### 2. Collect the reference assemblies

The build references game and mod assemblies that **cannot be redistributed**:
`Assembly-CSharp.dll` and the `UnityEngine.*` modules are the game vendor's copyrighted
files, and BepInEx / KmyTarkovApi are their authors' work.
`refs/` is therefore **git-ignored** and must be generated from your own installation.

```powershell
powershell -ExecutionPolicy Bypass -File tools\collect-refs.ps1 -GameRoot "C:\SPT"
```

The script copies from your install and reports anything missing:

| Reference | Source |
|---|---|
| `Assembly-CSharp.dll` | `<GameRoot>\EscapeFromTarkov_Data\Managed\` |
| `UnityEngine*.dll`, `Unity.TextMeshPro.dll`, `Newtonsoft.Json.dll`, `Comfort.dll` | ditto |
| `Sirenix.*.dll` | ditto |
| `BepInEx.dll`, `0Harmony.dll` | `<GameRoot>\BepInEx\core\` |
| `KmyTarkovApi.dll`, `KmyTarkovReflection.dll`, `KmyTarkovUtils.dll` | `<GameRoot>\BepInEx\plugins\kmyuhkyuk-KmyTarkovApi\` |
| `spt-common.dll` | `<GameRoot>\BepInEx\plugins\spt\` |

### 3. Build

```powershell
dotnet build GamePanelHUD.sln -c Release
```

Each module writes to `<Module>\bin\Release\`.

> **The solution contains exactly the seven modules that ship as DLLs.**
> `Build/`, `GamePanelHUDMap/` and `GamePanelHUDDebug/` are kept in the repository
> unchanged from upstream, but are **not** part of `GamePanelHUD.sln`: they are still
> `ToolsVersion 15.0` / `net472` projects (upstream's bundle packer and two dev tools)
> and would fail on any machine without the .NET Framework 4.7.2 targeting pack.
> None of them produces a file that ships in a release.
>
> To build a single module instead:
> ```powershell
> dotnet build GamePanelHUDCompass\GamePanelHUDCompass.csproj -c Release
> ```

### 4. Install

Copy the built DLLs over the mod's install folder, keeping the structure:

```
BepInEx/plugins/kmyuhkyuk-GamePanelHUD/
    GamePanelHUDCore.dll
    GamePanelHUDCompass.dll
    GamePanelHUDGrenade.dll
    GamePanelHUDHealth.dll
    GamePanelHUDHit.dll
    GamePanelHUDKill.dll
    GamePanelHUDWeapon.dll
```

The `.bundle` UI assets and `localized/` JSON ship in the release asset; they are
upstream art and are **not** regenerated by this source.

## What this port changes

| Area | Change |
|---|---|
| Target framework | `net472` → `netstandard2.1`; project files rewritten to SDK style |
| Plugin GUIDs | `com.kmyuhkyuk.*` → `com.dustinmoon78.*` (lowercase; the Forge enforces lowercase and the upstream namespace is taken) |
| Game API | Adapted to the 4.1.6 client surface (`Player.QuestController`, `IPlayer` kill callback signature, `ClientAirDrop._syncObject`, …) |
| Compass | Added VisitAPI story-zone markers (v4.0.1) — see below |

### VisitAPI story-zone markers (v4.0.1)

If [VisitAPI](https://hub.sp-tarkov.com/) (`com.sora.visitapi`) is installed, its story
quests place objectives at coordinates defined by content packs. The Compass module now
reads those zones and draws them as static markers, using the quest's trader avatar as
the icon:

| File | Role |
|---|---|
| `GamePanelHUDCompass/VisitApi/VisitZone.cs` | Parses `{ data: [...] }` from the server; field names follow `VisitAPI.Native.QuestZones` |
| `GamePanelHUDCompass/VisitApi/VisitZoneClient.cs` | `POST /visitapi/zones` on a background thread, cached |
| `GamePanelHUDCompass/VisitApi/VisitZoneStaticBuilder.cs` | Matches quest condition `zoneId` → zone → `StaticModel` |
| `GamePanelHUDCompass/Controllers/CompassStaticHUDController.cs` | Refresh loop, 5 s throttle |

It is a soft dependency: with VisitAPI absent the request fails once, is logged, and
native markers are unaffected. There is a F12 toggle under *Quest Display Settings*.
